# Per-Shot Motion (Studio `fal.video`)

**Status:** Implemented: planning, budgeted packets, governed import, film assembly and take planning.
No live generation executed. Veo and Runway are excluded by the controller, not by convention.

## What this is

Motion for one shot, generated by a cheap fal video model inside Studio, seeded with the shot's
approved still as the first frame.

```text
approved still (shot 03)
  → first-frame video generation (minimax/h3 @ 768p, 5s)
  → mp4 imported, hashed, settled against the plan item
  → available for assembly
```

It is **shot-based**, not one long text-to-video prompt. That is what keeps output affordable and
re-rollable.

## Flow

```powershell
pinaka plan-motion    <project> --file shot-motion.json   # estimate, no spend
pinaka prepare-motion <project> --file shot-motion.json   # reserve + write packet
# host runs Studio video.generate with the packet
pinaka import-motion  <project> --file motion-result.json # register clip + settle
```

`import-motion` accepts an optional `shot_id`; when given, the clip is attached to that shot as a
`motion` slot primary, so the composition uses it without further wiring.

## Composition

A shot with an attached clip renders it as a `<video class="layer clip">` layer covering the frame,
behind the text overlay.

- The authored HTML references the clip by `file://` URI; it is not base64-embedded.
- At `?t=` the inline script sets each clip's `currentTime` to the shot-local position.
- Any composition containing a clip is captured through **Playwright**, which waits for `seeked`
  before screenshotting; headless Chrome's one-shot screenshot cannot.
- Clip-free compositions keep using the faster Chrome capture.

Verified with a synthetic 5-second clip: 10 frames at 2 fps, the rendered frame at 2 s showed the
clip's own timecode at 2 with the beat text on top.

```json
{
  "shot_id": "shot_…",
  "route": "fal.video",
  "model": "minimax/h3",
  "mode": "first-frame",
  "resolution": "768p",
  "duration_seconds": 5,
  "prompt": "Slow push in as the duck glides across the pond.",
  "first_frame_artifact_id": "art_…",
  "plan_id": "budgetplan_…",
  "item_key": "shot-03-motion"
}
```

## Budget rules

| Rule | Effect |
|---|---|
| Plan item required | provider `studio-video`, operation `video.generate` |
| Estimate must match | the item's estimate must equal the model/duration/resolution estimate |
| Per-shot cap | above the automatic limit the request needs spend approval |
| Settlement | actual cost charged, reservation released, per-asset cost recorded |
| One take per request | no automatic retry; every take is a separate authorized spend |

The packet records `one_take_per_request: true` and `auto_retry: false` so a host cannot silently
re-roll.

## Take planning

```powershell
pinaka motion-takes <project> --model minimax/h3 --seconds 5 --resolution 768p
```

Returns how many takes fit the **remaining** budget without spending anything. Three takes of
`minimax/h3` at 768p cost 90 minor against a $10 balance; a $0.20 balance reports zero. The take count
is planned, not automatic: each take is still a separate authorized request, because Studio never
silently re-rolls.

## Assembly

```powershell
pinaka assemble-film <project> [--transition cut|dissolve] [--dissolve 0.4] [--fps 24]
```

- Every shot must have an attached clip; assembly refuses with the missing shot keys otherwise.
- Each clip is trimmed to its planned shot duration, scaled, padded to the target frame, and joined.
- `cut` concatenates; `dissolve` overlaps shots by `--dissolve` seconds with an `xfade`, so the film
  shortens by that amount per join.
- The result is a silent H.264 master (`renders/film-<hash>.mp4`) depending on every clip used.

Verified locally with two synthetic clips: cut produced 10.2 s, dissolve 9.3 s for the same shots.

## Choosing a model

| Need | Use |
|---|---|
| Bulk shots, best value | `minimax/h3` first-frame @768p |
| Hero shot, richer motion | `gemini-omni-flash/v1.2` @720p (fal-hosted, not Veo) |
| A beat longer than 15s | `ltx-2.5/fast` (up to 20s, one generation, no seam) |
| Keyframe in-between | `minimax/h3` first-and-last-frame |
| Restyle existing clip | `minimax/h3` video-to-video |

## Not in this path

- **Veo and Runway are excluded, not merely deprecated.** `ShotMotionRequest` accepts only
  `route="fal.video"` and refuses any `veo` model; `motion.assert_route` rejects every other route;
  `references.PROVIDER_FIELDS` contains only `fal.video`. There is no fallback path.
  Veo 3.1 is a temporary Google preview, and Runway routes have no key and spend Runway credits
  rather than the fal balance.
- No automatic retry, no speculative variants.
- Generated clips are imported, attached to their shot and rendered in the composition; full-film
  joining runs through `assemble-film`.

## Cost sanity

Eight 5-second shots at `minimax/h3` 768p is **$2.40**, leaving room to re-roll within a $10 balance.
Veo is not an option at any price, so there is no $8–16 comparison to make.
