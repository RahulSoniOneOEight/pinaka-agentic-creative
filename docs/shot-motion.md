# Per-Shot Motion (Studio `fal.video`)

**Status:** Implemented: planning, budgeted packets, and governed import. No live generation executed.

## What this is

Motion for one shot, generated by a cheap fal video model inside Studio, seeded with the shot's
approved still as the first frame.

```text
approved still (shot 03)
  → first-frame video generation (minimax/h3 @ 768p, 5s)
  → mp4 imported, hashed, settled against the plan item
  → available for assembly
```

It is **shot-based**, not one long text-to-video prompt. That is what keeps output affordable and
re-rollable.

## Flow

```powershell
pinaka plan-motion    <project> --file shot-motion.json   # estimate, no spend
pinaka prepare-motion <project> --file shot-motion.json   # reserve + write packet
# host runs Studio video.generate with the packet
pinaka import-motion  <project> --file motion-result.json # register clip + settle
```

```json
{
  "shot_id": "shot_…",
  "model": "minimax/h3",
  "mode": "first-frame",
  "resolution": "768p",
  "duration_seconds": 5,
  "prompt": "Slow push in as the duck glides across the pond.",
  "first_frame_artifact_id": "art_…",
  "plan_id": "budgetplan_…",
  "item_key": "shot-03-motion"
}
```

## Budget rules

| Rule | Effect |
|---|---|
| Plan item required | provider `studio-video`, operation `video.generate` |
| Estimate must match | the item's estimate must equal the model/duration/resolution estimate |
| Per-shot cap | above the automatic limit the request needs spend approval |
| Settlement | actual cost charged, reservation released, per-asset cost recorded |
| One take per request | no automatic retry; every take is a separate authorized spend |

The packet records `one_take_per_request: true` and `auto_retry: false` so a host cannot silently
re-roll.

## Choosing a model

| Need | Use |
|---|---|
| Bulk shots, best value | `minimax/h3` first-frame @768p |
| Hero shot, Veo-like look | `gemini-omni-flash/v1.2` @720p |
| A beat longer than 15s | `ltx-2.5/fast` (up to 20s, one generation, no seam) |
| Keyframe in-between | `minimax/h3` first-and-last-frame |
| Restyle existing clip | `minimax/h3` video-to-video |

## Not in this path

- **Veo and Runway are not part of the flow.** Veo 3.1 is a temporary Google preview; Runway routes
  exist in Studio but have no key and spend Runway credits, not the fal balance.
- No automatic retry, no speculative variants.
- Generated clips are not yet placed into the HTML composition; assembly currently uses the
  deterministic renderer and imported media separately.

## Cost sanity

Eight 5-second shots at `minimax/h3` 768p is **$2.40**, leaving room to re-roll within a $10 balance.
The same seconds on Veo would be $8–16 with no retry headroom.
